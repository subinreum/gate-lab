# Blind Spots

这里只写**当前仍然无法从仓内断言**的东西。已修掉的旧洞不算盲区，但可以记历史。

## 历史：第一版页面闸门拿引擎当 oracle

这条已经修掉，但值得记一笔，因为它太像“看起来覆盖到了其实没有”。

**旧形状。** 页面闸门把 DOM 跟 `diffLines()` 在 Node 里跑出来的结果比。引擎语义坏掉时，两边以完全相同的方式一起错，于是页面闸门依旧全绿。PR #5 第一跑（broken engine）真的是这样：引擎红、页面绿 18/18。

**为什么现在不算盲区。** 页面闸门已经改成拿 `scripts/dom-fixtures.mjs` 的手写期望比，且引擎闸门会守夹具本身：不得 import `src/`、至少一个夹具含 CJK、每个夹具都要能拓住「逐行对齐」变异体、每个夹具都要跟真引擎一致。

## 1. 字形保真度

`document.fonts.check` 能回答「有没有字形可用」，`textContent` 能回答「字符串是不是那串字」，
盒子尺寸能回答「这行有没有真的布局出来」。三者合起来仍然证不了“渲染出来的那个字形就是
人眼要看到的那个字，不是另一个 fallback 字体里形似但不对的字”。这件事最终要靠截图给人看，
或者另上一层 OCR / 图像比对。

## 2. 跨仓一致性没有全局观察者

ci-workflows 那条「全仓只允许一份 checkFreshness」只能看见它自己的目录，看不见本仓。
本仓也有对应断言，但那只是“各自守自己”，不是“有一处在守全体”。新增一个调用方时，
没有任何地方会提醒它需要这条断言。

## 3. 上游 `stats-marker` 默认值

gate-lab 从内部看不到 `attest.yml` 里的默认 `stats-marker`，所以无法断言它跟上游 manifest
登记的一致。这个值由上游自己的闸门守。

## 4. 整条 run 零个 job（startup_failure）

所有断言都活在 job 里。零个 job 执行时，没有任何代码有机会说话。在面板上，
「零条运行记录」和「还没开始跑」长得一模一样。实例：run `32698335732`。
