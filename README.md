# gate-lab

一个静态网页文本差异对比器。

## 质量门

- **引擎闸门**：纯核心语义 + 仓内约束（集合相等、钉版本、不得内联第二份新鲜度逻辑）
- **页面闸门**：无头浏览器驱真实页面，逐行核 DOM 输出
- **共享回写**：[`subinreum/ci-workflows`](https://github.com/subinreum/ci-workflows) 的 `report.yml`
- **共享送达核对**：同一个仓的 `attest.yml`，跟上游用**同一份**新鲜度比较器

## 为什么浏览器闸门单独跑

因为引擎绿不等于页面能用。最经典的坑就是：核心算法没错，但页面脚本没加载、按钮没绑定、DOM 一行都没渲染出来。只看引擎报告，两边都会是绿的。

## 为什么送达核对不在本仓手写

因为它已经出过事了。上游把新鲜度断言加硬了（评论正文里的 run id 必须等于本次 run id），而本仓第一版自己手写了一份只查 marker 的版本，于是同一个洞原样复发：回写静默失败时读到上一跑的残留然后照样绿。

模板级修复不能靠“每个仓再写一遍”传染。两个仓引用同一个文件才叫一致。

## 为什么钉住 Playwright

因为这是时间驱动的漂移：你一行代码都不推，页面闸门的行为也会变。版本字面只写在 `package.json`，workflow 从那里读，浏览器闸门再把**实际装上的**版本跟钉的版本对一次。钉了不等于装对了。

## 为什么这里先用 `@main`

这里是 `ci-workflows` 的**第一个跨仓库调用方**。这次有意先用 `@main` 把跨仓库权限、令牌、回写链路跑通，不把“固定版本”当成默认好习惯。代价也明确：它是可变引用，上游改一行就能静默改掉这边所有流水线的行为。继续沿用或 bump 之前，先读上游 diff。
